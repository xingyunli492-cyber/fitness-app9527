## 2. 项目成果

本系统面向减脂健身人群，实现了「记录—核算—推荐」的核心闭环：

1. **饮食热量记录**：内置 21 种常见食物，按克数自动核算摄入热量。
2. **运动消耗统计**：内置 12 种常见运动（含 MET 值），按时长与体重自动核算消耗。
3. **个性化方案推荐**：基于 Mifflin-St Jeor 公式计算基础代谢 BMR，结合活动系数得 TDEE，再按减脂目标扣除热量缺口，生成每日摄入目标与三大营养素配比。
4. **仪表盘可视化**：今日热量平衡概览 + 近 7 日趋势图。
5. **移动端界面**：底部 Tab 导航，适配手机屏幕。

## 3. 核心算法

| 指标 | 公式 |
|------|------|
| 基础代谢 BMR | Mifflin-St Jeor 公式 |
| 每日总消耗 TDEE | BMR × 活动系数（1.2~1.9） |
| 热量缺口 | 温和 300 / 标准 500 / 强化 700 kcal |
| 目标摄入 | max(TDEE - 缺口, 1200) |
| 运动消耗 | MET × 体重 × 时长 |
| 食物热量 | 每100g热量 × 克数 / 100 |

## 6. 经验与教训

1. **算法与数据解耦的价值**：将核心计算抽成纯函数模块，使单元测试能独立进行，覆盖率达 100%，这是本项目最有价值的工程实践。
2. **移动端优先**：前期按桌面端设计，后期改为移动端，走了弯路。若一开始就用移动端优先的响应式设计，可节省返工。
3. **编码问题需提前约定**：bat 脚本与中文编码的兼容问题曾导致乱码，教训是涉及脚本文件时优先用英文命名或明确约定编码。
4. **范围控制**：Vision 文档规划了多用户、管理后台等大范围功能，实际按单用户核心闭环聚焦实现，通过优先级裁剪保障了进度。

## 7. 不足与展望

1. 当前为单用户本地版，后续可扩展多用户与云端部署。
2. 食物库规模有限，可扩充条码扫描、拍照识别等便捷录入方式。
3. 推荐方案基于通用公式，可引入更智能的个性化算法。

## 8. 结论

本项目完整经历了需求分析、架构设计、编码实现与测试验收的软件工程全流程，交付了可运行的减脂热量管理系统，核心算法科学可靠，工程质量达到课程要求，达成了项目目标。
