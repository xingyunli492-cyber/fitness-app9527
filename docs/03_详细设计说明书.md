## 2. 算法模块详细设计（algorithms.py）

### 2.1 活动水平与减脂目标常量

```python
ACTIVITY_LEVELS = {
    "sedentary": {"factor": 1.2, ...},
    "light":     {"factor": 1.375, ...},
    "moderate":  {"factor": 1.55, ...},
    "high":      {"factor": 1.725, ...},
    "extreme":   {"factor": 1.9, ...},
}

GOAL_DEFICIT = {
    "mild":   {"deficit": 300, ...},
    "normal": {"deficit": 500, ...},
    "strict": {"deficit": 700, ...},
}
```

### 2.2 calc_bmr 实现逻辑

```
输入：gender, age, height_cm, weight_kg
过程：
    base = 10*weight_kg + 6.25*height_cm - 5*age
    if gender == male: return base + 5
    if gender == female: return base - 161
输出：BMR（kcal/天）
```

### 2.3 calc_target_intake 实现逻辑

```
输入：tdee, goal
过程：
    deficit = GOAL_DEFICIT[goal]["deficit"]
    target = tdee - deficit
    return max(target, 1200)   # 安全下限保护
```

### 2.4 build_recommendation 实现逻辑

```
输入：gender, age, height_cm, weight_kg, activity_level, goal
过程：
    bmr = calc_bmr(...)
    tdee = calc_tdee(bmr, activity_level)
    target = calc_target_intake(tdee, goal)
    deficit = tdee - target
    # 营养素：蛋白30%/碳水40%/脂肪30%
    protein_g = max(target*0.30/4, weight_kg*1.8)
    carb_g = target*0.40/4
    fat_g = target*0.30/9
    water_ml = weight_kg*40
输出：字典，含 bmr/tdee/target/deficit/营养素等
```

### 2.5 daily_summary 实现逻辑

```
输入：target_intake, intake, burned
过程：
    net = intake - burned          # 净摄入
    remaining = target_intake - net
    状态判定：
        |remaining| <= 100 → "达标"
        remaining < -100   → "超了"
        否则              → "可多吃"
```

## 3. 数据层详细设计（database.py）

### 3.1 连接管理

```python
def get_conn():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row   # 支持列名访问
    return conn
```

### 3.2 初始化流程

```
init_db():
    1. 执行建表 SQL（IF NOT EXISTS）
    2. 若 foods 表为空 → 写入 21 种食物种子数据
    3. 若 exercises 表为空 → 写入 12 种运动种子数据
    4. 若 user_profile 为空 → 写入默认档案
```

### 3.3 关键 SQL

```sql
-- 建表
CREATE TABLE IF NOT EXISTS user_profile (...);
CREATE TABLE IF NOT EXISTS foods (...);
CREATE TABLE IF NOT EXISTS exercises (...);
CREATE TABLE IF NOT EXISTS diet_records (...);
CREATE TABLE IF NOT EXISTS exercise_records (...);

-- 统计某日摄入
SELECT COALESCE(SUM(calories), 0) FROM diet_records WHERE record_date = ?;

-- 近 N 日汇总（循环逐日查询）
```

### 3.4 种子数据设计

- 食物库 21 种：覆盖主食（米饭/馒头/面条/全麦面包/燕麦/红薯）、肉蛋（鸡胸肉/鸡蛋/瘦牛肉/猪瘦肉/三文鱼）、蔬果（西兰花/生菜/番茄/苹果/香蕉）、乳制品（牛奶/酸奶）、零食饮品（可乐/薯片/坚果）。
- 运动库 12 种：快走、慢跑、跑步、骑行、跳绳、游泳、篮球、羽毛球、力量训练、瑜伽、爬楼梯、HIIT，含对应 MET 值。

## 5. 前端详细设计

### 5.1 模板继承

`base.html` 定义导航栏、内容区、页脚与静态资源引用，各页面通过 `{% extends "base.html" %}` 继承，在 `{% block content %}` 中填充内容。

### 5.2 前端交互（main.js）

- 搜索过滤：监听输入框 `input` 事件，按名称前缀匹配显示/隐藏列表项。
- 添加记录：点击按钮后读取食物/运动 ID 与克数/时长，`fetch` 调 POST API，成功后刷新页面。
- 删除记录：点击删除按钮，`confirm` 确认后 `fetch` 调 DELETE API，成功后刷新。

## 6. 异常处理设计

| 场景 | 处理 |
|------|------|
| 食物/运动 ID 不存在 | API 返回 404 与错误信息 |
| 非法输入（克数/时长为空或≤0） | 前端 `alert` 拦截 |
| 页面不存在 | 自定义 404 页面 |
| 摄入低于安全下限 | `max(target, 1200)` 保护 |
| 未知性别/活动水平/目标 | 抛 `ValueError`，由开发者修复配置 |
