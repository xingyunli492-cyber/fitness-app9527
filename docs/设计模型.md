# 设计模型（Design Model）

## 1. 类图

本系统采用分层结构，核心为算法模块 `algorithms.py` 与数据模块 `database.py`，二者解耦，由 `app.py` 编排。

```mermaid
classDiagram
    class algorithms {
        +calc_bmr(gender, age, height_cm, weight_kg) float
        +calc_tdee(bmr, activity_level) float
        +calc_target_intake(tdee, goal) float
        +calc_exercise_calories(met, weight_kg, minutes) float
        +calc_food_calories(calories_per_100g, amount_g) float
        +build_recommendation(...) dict
        +daily_summary(target_intake, intake, burned) dict
    }

    class database {
        +get_conn() Connection
        +init_db() None
        +get_profile() dict
        +update_profile(...) None
        +add_diet_record(...) None
        +add_exercise_record(...) None
        +get_diet_records(date) list
        +get_exercise_records(date) list
        +delete_diet_record(id) None
        +delete_exercise_record(id) None
        +search_foods(keyword) list
        +search_exercises(keyword) list
        +sum_diet_calories(date) float
        +sum_exercise_calories(date) float
        +recent_days_summary(days) list
    }

    class app {
        +index()
        +diet()
        +exercise()
        +recommend()
        +profile()
        +api_add_diet()
        +api_add_exercise()
    }

    app --> algorithms : 调用
    app --> database : 调用
    database --> SQLite : 持久化
```

## 3. 关键流程时序（记录饮食）

```mermaid
sequenceDiagram
    participant U as 用户(浏览器)
    participant A as app.py
    participant AL as algorithms
    participant DB as database

    U->>A: POST /api/diet {food_id, amount_g}
    A->>DB: get_food_by_id(food_id)
    DB-->>A: food 记录
    A->>AL: calc_food_calories(每100g热量, amount_g)
    AL-->>A: calories
    A->>DB: add_diet_record(...)
    DB-->>A: 保存成功
    A-->>U: {ok: true, calories}
```

## 4. 设计要点

- **算法与数据解耦**：`algorithms.py` 为纯函数模块，不依赖数据库，可独立单元测试。
- **记录冗余食物名**：饮食/运动记录表冗余存储名称，避免关联查询，适配单用户轻量场景。
- **单用户模型**：`user_profile` 仅维护一行（id=1），简化鉴权与数据隔离。
- **统计实时计算**：热量汇总通过 SQL 聚合即时计算，不落库冗余，保证一致性。
