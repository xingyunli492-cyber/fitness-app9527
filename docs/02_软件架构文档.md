# 软件架构文档

## 1. 引言

### 1.1 编写目的

本文档描述系统的总体架构、架构风格、模块划分、数据模型与核心算法，作为技术原型迭代（迭代二）的核心交付物，指导详细设计与编码实现。

### 1.2 技术选型

| 项 | 选型 | 说明 |
|----|------|------|
| 编程语言 | Python 3.12 | 面向对象语言，团队掌握 |
| Web 框架 | Flask 3.1 | 轻量，适合单用户本地部署 |
| 数据库 | SQLite | 零配置本地存储，标准库 sqlite3 |
| 前端 | Jinja2 模板 + 原生 HTML/CSS/JS | 移动端优先，响应式 |

> 说明：Vision 文档阶段推荐 FastAPI + MySQL + Vue，经技术原型迭代评审，考虑到「新技术不超过 2 项」的约束与单用户本地部署的定位，最终基线化为 Flask + SQLite 的轻量方案，本文档以下内容均以该基线为准。

## 2. 架构风格与设计模式

### 2.1 架构风格

系统采用 **分层架构（Layered Architecture）** 结合 **MVC 模式**：

- **分层架构**：表示层、控制层、业务层、数据层职责分离，层间单向依赖（上层依赖下层），降低耦合。
- **关注点分离**：算法（业务逻辑）与数据访问彻底解耦，`algorithms.py` 为纯函数模块，不依赖数据库与框架，可独立单元测试。

### 2.2 设计模式

| 模式 | 应用位置 | 说明 |
|------|---------|------|
| 数据访问对象（DAO） | database.py | 封装所有 SQLite 操作，上层无需感知 SQL 细节 |
| 门面（Facade） | app.py | 统一入口，编排算法与数据层，对外提供页面与 API |
| 表驱动 | algorithms.py 的常量字典 | 活动系数、热量缺口以字典配置，便于扩展 |

## 3. 总体架构

系统采用分层架构 + MVC 模式：

```
┌─────────────────────────────────────────┐
│              浏览器（前端）                │
│   HTML / CSS / JavaScript（Jinja2 模板）  │
└──────────────────┬──────────────────────┘
                   │ HTTP / JSON
┌──────────────────▼──────────────────────┐
│              Flask 应用层                 │
│   app.py（路由 + REST API + 页面渲染）     │
└──────────┬───────────────────┬──────────┘
           │                   │
┌──────────▼──────────┐  ┌─────▼────────────┐
│   algorithms.py      │  │   database.py     │
│   算法层（纯函数）     │  │   数据访问层       │
│  BMR/TDEE/缺口/推荐   │  │  sqlite3 CRUD     │
└─────────────────────┘  └─────┬────────────┘
                               │
                        ┌──────▼──────┐
                        │  SQLite DB   │
                        │  fitness.db  │
                        └─────────────┘
```

### 分层职责

| 层 | 模块 | 职责 |
|----|------|------|
| 表示层 | templates/ + static/ | 页面展示与交互 |
| 控制层 | app.py | 路由分发、参数校验、调用业务逻辑 |
| 业务层 | algorithms.py | 核心算法，纯函数无副作用，便于单元测试 |
| 数据层 | database.py | 数据库连接、建表、种子数据、CRUD |

> 算法层与数据层解耦，`algorithms.py` 不依赖数据库，可独立进行单元测试。

## 3. 模块划分

### 3.1 算法模块（algorithms.py）

- `calc_bmr(gender, age, height_cm, weight_kg)` — 基础代谢计算
- `calc_tdee(bmr, activity_level)` — 每日总消耗计算
- `calc_target_intake(tdee, goal)` — 目标摄入计算
- `calc_exercise_calories(met, weight_kg, minutes)` — 运动消耗计算
- `calc_food_calories(calories_per_100g, amount_g)` — 食物热量计算
- `build_recommendation(...)` — 综合推荐方案
- `daily_summary(target_intake, intake, burned)` — 每日汇总

### 3.2 数据模块（database.py）

- `init_db()` — 建表 + 种子数据
- 用户档案 CRUD：`get_profile` / `update_profile`
- 记录 CRUD：`add_diet_record` / `add_exercise_record` / `get_*` / `delete_*`
- 库查询：`search_foods` / `search_exercises`
- 统计：`sum_diet_calories` / `sum_exercise_calories` / `recent_days_summary`

### 3.3 应用模块（app.py）

- 页面路由：`/`、`/diet`、`/exercise`、`/recommend`、`/profile`
- REST API：`/api/*`（供前端 AJAX 调用）

## 5. 核心算法设计

### 5.1 基础代谢（Mifflin-St Jeor）

```
男：BMR = 10×体重 + 6.25×身高 - 5×年龄 + 5
女：BMR = 10×体重 + 6.25×身高 - 5×年龄 - 161
```

### 5.2 每日总消耗

```
TDEE = BMR × 活动系数
活动系数：久坐1.2 / 轻度1.375 / 中度1.55 / 高度1.725 / 极高1.9
```

### 5.3 热量缺口与目标摄入

```
目标摄入 = max(TDEE - 缺口, 1200)
缺口：温和300 / 标准500 / 强化700 kcal
```

### 5.4 运动消耗（MET 法）

```
消耗(kcal) = MET × 体重(kg) × 时长(小时)
```

### 5.5 营养素配比

减脂期供能比：蛋白质 30% / 碳水 40% / 脂肪 30%。
每克供能：蛋白质 4 kcal、碳水 4 kcal、脂肪 9 kcal。
蛋白质同时按体重 1.8g/kg 修正，取较大值。

## 6. 接口设计

### 6.1 页面路由

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | / | 仪表盘 |
| GET | /diet | 饮食记录页 |
| GET | /exercise | 运动记录页 |
| GET | /recommend | 方案推荐页 |
| GET/POST | /profile | 个人档案 |

### 6.2 REST API

| 方法 | 路径 | 功能 |
|------|------|------|
| POST | /api/diet | 新增饮食记录 |
| POST | /api/exercise | 新增运动记录 |
| DELETE | /api/diet/{id} | 删除饮食记录 |
| DELETE | /api/exercise/{id} | 删除运动记录 |
| GET | /api/recommend | 获取推荐方案 |
| GET | /api/summary/{date} | 获取某日汇总 |

## 7. 界面设计

导航栏含五个页面：仪表盘、饮食记录、运动记录、方案推荐、个人档案。整体采用卡片式布局，主色为绿色（健康主题），响应式适配移动端。
